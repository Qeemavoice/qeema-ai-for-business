# New Qeema Voice UI on the Laravel backend

The React site (`new-ui/`, formerly the standalone Node project) is served by this Laravel 8 application.
Laravel + MySQL stay the source of truth: users, voices, orders, articles, guides, FAQs, pages, careers,
contact messages and the mailing list are read from and written to the **existing tables**. Only new
features (TTS studio, credits, narrator dashboard state, success stories, page texts, voice templates…)
use new `qv_*` tables. The old admin panel at `/ar/dashboard/...` is untouched.

## What is where

| Piece | Location |
|---|---|
| React source | `new-ui/` (build with `npm run build:laravel`) |
| Built site served to visitors | `public/new-ui/` (committed) + media in `public/assets/aistudio`, `public/stories`, `public/logo-motion`, `public/qv-chat` |
| Page routes (SPA shell, 301s of old URLs, sitemap, robots) | `routes/newui.php`, `app/Http/Controllers/NewUi/SpaController.php`, `SitemapController.php` |
| API `/api/v1/*` | `routes/newui_api.php`, controllers in `app/Http/Controllers/NewUi/`, services in `app/Services/NewUi/` |
| New tables | `database/migrations/2026_11_05_000001_create_qv_tables.php` |
| Dashboard content at integration time | `database/seeders/NewUiSeeder.php` + `database/seeders/data/new-ui-seed.json` |
| Registration | `app/Providers/RouteServiceProvider.php` (`mapNewUiRoutes`, before the old app routes), `app/Http/Kernel.php` (`qv.user`, `qv.admin`), `app/Models/User.php` (`HasApiTokens`) |

## Deploy steps

```bash
composer install            # Sanctum is already in composer.json
php artisan migrate         # creates the qv_* tables, adds mail_messages.qv_status (nullable)
php artisan db:seed --class=NewUiSeeder
php artisan storage:link    # not required, generated audio is streamed by the API
php artisan route:clear && php artisan config:clear
```

`.env` additions (all optional):

```
SITE_URL=https://qeemavoice.com     # used in invitation / team e-mails
ELEVENLABS_API_KEY=                  # TTS with ElevenLabs voices (also settable in the new admin «الإعدادات»)
ELEVENLABS_AGENT_ID=                 # assistant voice widget
GEMINI_API_KEY=                      # assistant chat
```

Google sign-in reuses `services.google.client_id` (Socialite) from `config/services.php`.
E-mails (verification codes, invitations) use the site's normal `MAIL_*` mailer unless an SMTP server is
saved in the new admin dashboard «إعدادات SMTP».

To rebuild the front end after editing `new-ui/src`:

```bash
cd new-ui && npm install && npm run build:laravel     # writes ../public/new-ui
```

## URLs

* Same public URLs as before (`/ar`, `/ar/voices`, `/ar/blogs/details/{id}-{title}`, `/ar/booking/{id}-{title}`,
  `/ar/guides/{id}-{title}`, `/ar/p/about-us`, …). Old list-page slugs (`/ar/voices/{slug}`, `/ar/categories/{slug}`,
  `/ar/blogs/{slug}`, `/ar/faqs/{slug}`, `/ar/contact-us/{slug}`, `/ar/booking-steps/{slug}`, `/ar/our-works/{slug}`,
  `/ar/careers`, `/ar/jobs/details/{slug}`) answer **301** to the new page.
* `/sitemap.xml` and `/robots.txt` are generated by the new site (static pages + articles + stories + library voices).
* New client dashboard: `/ar/account` (was `/ar/dashboard` in the Node prototype; `/ar/dashboard/...` is the old back office).
  New admin dashboard: `/ar/admin`. Narrator dashboard: `/ar/talent-dashboard`. Invitation links: `/claim/{token}`.
* Old client/voice-actor Vue pages (`/ar/clients/...`, `/ar/voice-actors/...`, chat) still exist but are no longer linked.

## Data mapping

| New UI | Table |
|---|---|
| Accounts, sign-in (Bearer tokens) | `users` (+ `personal_access_tokens`) — passwords unchanged, admins = `role_id` administration / user type admin / «إدارة المشرفين» |
| Client workspace: plan, projects, team invites, favourites | `qv_client_accounts` |
| Credits ledger | `qv_credit_transactions` |
| TTS generations / narrator earnings | `qv_generations`, `qv_narrator_earnings`, audio in `storage/app/qv-audio` |
| TTS studio voices | `qv_tts_voices` |
| Human voice library | `voices` (accepted) + samples approved in the new narrator dashboard (approval also inserts a `voices` row) |
| Bookings | `orders` + `order_items` + `order_item_details` (status pending), extra fields in `qv_booking_meta` |
| Narrator dashboards (profiles, samples, contracts, AI voice, notifications) | `qv_kv` key `narratorState`, auto-filled from voice-actor `users` and `user_samples` |
| Blog, guides, FAQs, pages, jobs, categories, dialects/languages | `articles`, `guides`, `faqs`, `pages`, `careers`, `categories`, `dialects`/`languages` |
| Contact / project / demo requests, narrator payout & emergency requests | `mail_messages` (+ `qv_status` read/unread) |
| Newsletter | `mailing_lists` |
| Success stories, page texts, voice templates, services list, feedback, talent applications, supervisors | `qv_collections` |
| Settings (commission %, maintenance, currency, Stripe/SMTP/ElevenLabs keys) | `qv_kv` |

The platform commission of the new UI is 30 % on top of the narrator price (`qv_kv` → settings), independent of the
old `COMMISSION_PLATFORM` (9 %) used by the old booking form.

## Verified (2026-11-05, PHP 8.1 + SQLite test database)

Migrations and the seeder run; the SPA pages, server-side SEO tags, sitemap/robots, the 301s of old URLs and the old
admin login page answer; public lists, contact/newsletter/project forms, the free TTS trial and voice previews work;
signup/login/logout (Sanctum tokens), credits, TTS generation (internal engine), usage, billing, favourites, projects,
team invites; bookings as client and as guest (rows in `orders`, `order_items`, `order_item_details`, `qv_booking_meta`),
client reviews, admin review approval and public rating; every admin screen (overview, bookings + status, payouts,
customers, settings with masked secrets, all collections incl. articles/FAQs/guides/pages/dialects/categories on the old
tables, TTS voices, credit grants); narrator state with the admin-only field protection, sample approval into `voices`,
invitation → e-mailed code → claim (sets the password of the old account) → login, e-mail change with code.

Facts about the old schema learned on the way (handled in the code): `users` rating columns have no default,
`orders` has no tax columns, `order_item_details` has no price column, `voices.total_price` is required,
`voice_categories` has no timestamps, the old `HasTimestamps` trait returns `created_at` as a formatted string, and
`MailConfigServiceProvider` replaces the mail config with the SMTP account of the old admin panel.
Pre-existing bug left untouched: `routes/app.php` points `/ar/careers` at a controller class that does not exist
(`php artisan route:list` fails on it); the new 301 answers that URL first.

## Not covered yet

* Payments: plan upgrades and credit top-ups add credits without charging (Stripe keys are stored, not used).
* Narrator payouts are recorded as requests/settlements only (no transfer, no link to the old `wallets`).
* AI voice cloning in the narrator dashboard is a demo until an ElevenLabs key is set.
* No SMS provider: everything goes by e-mail.
